# page-tune — 웹페이지 등록·Tune 적용 열람 (UC2)

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | spec_page_view |
| 작성자 | dohwan.ahn |
| 작성일 / 최종 수정일 | 2026-11-06 / 2026-11-07 |

- **기능명:** 웹페이지 등록·Tune 적용 열람 — 웹페이지를 Tune 과 묶어 등록하고, 열 때마다 Tune 을 적용해 본다.
- **목적 (Why):**
  - UC1 에서 만든 Tune 을 실제로 쓰는 경로다.
  - 열람 화면에 조작 UI 가 없다 → 뒤로가기를 누르면 이전 페이지가 아니라 화면이 닫히고, 새로고침·주소 공유·Tune 확인 수단이 없다.
  - Tune 을 고치려면 목록 → Tune 탭 → 편집 → 주소 재입력 → 저장 → 다시 열기를 거쳐야 한다.

## 2. 목표 및 범위

### In Scope

- 현재 동작(as-built): 웹페이지 목록·등록·편집·삭제, 열람 화면, Tune 적용(숨기기·색·시작 위치·이전/다음·두 번 탭), 마지막 주소 기억
- GH-18: 이 UC 화면의 문자열 리소스화와 한국어
- GH-19: 웹페이지 다이얼로그 제목 표시, 열람 화면 뒤로가기
- GH-20: 웹페이지 탭 빈 상태, 벡터 아이콘, 접근성 핵심
- GH-21: 색 적용의 불안정 id 처리, 숨기기의 유효하지 않은 셀렉터 처리
- GH-22: 열람 화면 빠른 메뉴, Tune 상태 표시, 열람 중 Tune 편집 후 즉시 반영

### Out of Scope

- Tune 적용 범위를 URL·호스트로 제한하는 기능 → 현재처럼 이동한 모든 페이지에 적용된다 (§6.1)
- 다른 앱의 링크를 받아 여는 기능, 주소창 입력, 탭·히스토리
- 오류 화면, `intent://`·다운로드 등 외부 링크 처리
- 삭제 되돌리기, 목록 카드 개편, 온보딩

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 사용자로서, 자주 보는 페이지를 Tune 과 함께 등록해 한 번에 다듬어진 화면으로 열고 싶다 [as-built]
- `US#2` 사용자로서, 글을 넘겨 보다가 뒤로가기 한 번으로 목록에 돌아가고, 필요하면 이전 글로도 돌아가고 싶다 [요구사항] GH-19, GH-47
- `US#3` 사용자로서, 보고 있는 페이지에서 바로 Tune 을 고치고 결과를 바로 보고 싶다 [요구사항] GH-22
- `US#4` 사용자로서, 지금 Tune 이 적용됐는지 알고 필요하면 잠깐 끄고 원래 페이지를 보고 싶다 [요구사항] GH-22

### 3.2 기능 요구사항

#### 웹페이지 목록 (Web Pages 탭)

- `FR#1` 목록은 최근 등록 순으로 제목·주소·연결된 Tune 이름(없으면 없음 표시)을 보여주고, 항목을 누르면 열람 화면을, 편집 아이콘을 누르면 편집 다이얼로그를 연다 [as-built]
- `FR#2` 등록·편집 다이얼로그는 제목·주소·Tune(없음 포함)을 받는다 [as-built]

  ```
  Given 제목이나 주소가 비어 있다
  When  저장한다
  Then  저장하지 않고 모두 입력하라는 안내를 보인다
  ```

  - 주소에 scheme 이 없으면 `https://` 를 붙여 저장한다.
- `FR#3` 삭제는 툴바 삭제 → 선택 모드(전체 선택 가능) → 확인 다이얼로그 순서다. 선택 없이 확인하면 안내만 한다 [as-built]
- `FR#23` 삭제 선택 모드에서 항목의 체크박스를 직접 탭해도 항목(카드)을 탭한 것과 같은 선택 상태가 된다. 구현과 TC 는 `spec_tune_edit.md` FR#23·TC#35·TC#36 과 같다 [요구사항] GH-37
- `FR#4` 다이얼로그 제목("웹페이지 추가" / "웹페이지 편집")이 배경과 구분돼 읽힌다 [요구사항] GH-19
- `FR#5` 웹페이지가 하나도 없으면 목록 자리에 설명 한 줄과 "웹페이지 추가" 행동 버튼을 보이고, 버튼은 등록 다이얼로그를 연다 [요구사항] GH-20

#### 열람 화면

- `FR#6` 열람 화면은 상태바를 숨기고 노치까지 쓰는 전체화면이며, 내비게이션 바만 피한다. 로딩 중에는 상단 진행 막대를 보인다 [as-built]
- `FR#7` 화면을 열 때 웹페이지와 연결된 Tune 의 규칙을 한 번 읽고, 저장된 주소를 연다 [as-built]

  ```
  Given 웹페이지 id 가 없거나 DB 에 없다
  When  열람 화면을 연다
  Then  오류 안내 후 화면을 닫는다
  ```

  ```
  Given 연결된 Tune 이 없거나 삭제됐다
  When  열람 화면을 연다
  Then  Tune 없이 페이지를 연다
  ```

- `FR#8` 페이지 로드가 끝날 때마다 색 → 숨기기 → 시작 위치 순으로 적용한다 (§6.1) [as-built]
- `FR#9` 이전/다음 클릭 연결이 있으면 하단에 이전·다음 버튼 바를 보이고, 누르면 연결된 요소를 클릭한다 [as-built]
- `FR#10` 위/아래 두 번 탭 클릭 연결이 있으면, 화면 위쪽 N% 또는 아래쪽 N% 에서 두 번 탭할 때 연결된 요소를 클릭한다 [as-built]
  - N 은 위쪽 규칙의 값을 우선하고, 없으면 아래쪽 규칙의 값이다.
- `FR#11` 같은 호스트 안에서 이동하면 웹페이지의 저장 주소를 이동한 주소로 바꾼다 → 다음에 열면 마지막 위치에서 시작한다 [as-built]
  - 다른 호스트, 호스트명에 `cloudflare` 또는 `challenges` 가 들어간 주소, 파싱할 수 없는 주소로 이동하면 바꾸지 않는다.
- `FR#12` 페이지 로드가 끝날 때마다 쿠키를 디스크에 내린다 → 앱이 종료돼도 사이트 통과 쿠키가 남는다 [as-built]
- `FR#13` 시스템 뒤로가기(버튼·제스처)는 열람 화면을 닫고 목록으로 돌아간다. 빠른 메뉴 '뒤로'는 WebView 에 이전 페이지가 있으면 그 페이지로, 없으면 열람 화면을 닫는다 [요구사항] GH-19, GH-47

  ```
  Given 열람 화면에서 링크로 두 번 이동했다
  When  시스템 뒤로가기를 누른다
  Then  목록으로 돌아간다
  ```

  ```
  Given 열람 화면에서 링크로 두 번 이동했다
  When  빠른 메뉴 '뒤로'를 세 번 누른다
  Then  두 번은 이전 페이지로 돌아가고, 세 번째에 목록으로 돌아간다
  ```

#### 빠른 메뉴·Tune 상태 (GH-22)

- `FR#14` 화면 오른쪽 위 구석의 작은 반투명 핸들 버튼을 누르면 상단에 빠른 메뉴 툴바가 나타나고, 다시 누르면 숨는다 [요구사항] GH-22
  - 핸들은 디스플레이 컷아웃·둥근 모서리 안쪽에 두고 터치 영역은 48dp 이상이다.
  - 툴바는 마지막 조작 후 4초가 지나면 자동으로 숨는다. API 29 이상에서는 이 값을 접근성 설정의 권장 시간으로 늘린다 (§6.6 D#3).
  - API 24~28 은 권장 시간 API 가 없어 4초로 고정된다 → 이 범위에서는 사용자가 숨김 시간을 늘릴 수 없다 (WCAG 2.2.1 미충족). 핸들을 다시 누르면 언제든 다시 열 수 있다.
  - 툴바를 조작하는 동안에는 자동 숨김 타이머를 다시 시작한다.

  ```
  Given 빠른 메뉴 툴바가 열려 있다
  When  4초 동안 아무것도 누르지 않는다
  Then  툴바가 숨고 핸들만 남는다
  ```

- `FR#15` 빠른 메뉴 항목은 뒤로, 새로고침, 주소 공유, Tune 켜기/끄기, 이 페이지에서 Tune 편집이다 [요구사항] GH-22
  - 뒤로는 FR#13 과 같다.
  - 주소 공유는 현재 주소를 시스템 공유 시트로 보낸다.
  - 연결된 Tune 이 없으면 Tune 켜기/끄기는 비활성이고, Tune 편집 항목은 "이 페이지에 Tune 만들기" 가 된다 (FR#19).
- `FR#16` Tune 을 끄면 페이지를 다시 로드하고 Tune 을 적용하지 않는다. 켜면 다시 로드하고 적용한다 [요구사항] GH-22
  - 끈 상태는 이 열람 화면에만 유지한다. 화면을 나가면 해제되고 저장하지 않는다 (§6.6 D#4).

  ```
  Given Tune 이 적용된 페이지를 보고 있다
  When  빠른 메뉴에서 Tune 을 끈다
  Then  숨겨졌던 요소와 원래 색이 보이고, 이전/다음 버튼과 두 번 탭 동작이 멈춘다
  ```

- `FR#17` 이 페이지에서 Tune 편집을 고르면 연결된 Tune 의 편집 화면을 현재 주소로 연다 [요구사항] GH-22
  - 현재 주소를 로드 주소 인자로 넘긴다. 편집 WebView 는 현재 주소를 열고, 테스트 주소 칸과 저장되는 `testUrl` 은 기존 값을 유지한다 (`spec_tune_edit.md` §4.4).
- `FR#18` 편집 화면에서 저장하고 돌아오면 열람 화면이 규칙을 다시 읽고 Tune 을 켠 상태로 페이지를 다시 로드한다. 취소하고 돌아오면 아무것도 바꾸지 않는다 [요구사항] GH-22

  ```
  Given 열람 중 Tune 편집으로 숨기기를 하나 추가했다
  When  저장하고 돌아온다
  Then  열람 화면에서 그 요소가 숨겨져 있다
  ```

- `FR#19` 연결된 Tune 이 없는 웹페이지에서 "이 페이지에 Tune 만들기" 를 고르면 새 Tune 편집 화면을 현재 주소로 연다 [요구사항] GH-22
  - 현재 주소를 로드 주소 인자로, 이 웹페이지 id 를 연결할 웹페이지 id 인자로 넘긴다. 새 Tune 의 테스트 주소는 현재 주소다 (`spec_tune_edit.md` §4.4).
  - 연결은 편집 화면의 저장 트랜잭션이 한다 (`spec_tune_edit.md` FR#21). 저장하고 돌아오면 열람 화면은 웹페이지와 Tune 을 DB 에서 다시 읽어 FR#18 과 같이 바로 적용한다.
  - 취소하고 돌아오면 Tune 을 만들지도 연결하지도 않는다.

  ```
  Given Tune 이 연결되지 않은 웹페이지를 보고 있다
  When  이 페이지에 Tune 만들기 → 숨기기 하나 추가 → 저장하고 돌아온다
  Then  그 요소가 숨겨져 있고, 웹페이지 목록에 새 Tune 이름이 연결돼 보인다
  ```

- `FR#20` 열람 화면에 들어오거나 Tune 을 켜고 끌 때 Tune 상태를 잠깐 보인다 [요구사항] GH-22
  - 켜진 상태: 저장된 규칙 수를 종류별(숨기기·색상·이전/다음 이동·시작 위치)로 보이고, 0개인 종류는 생략한다.
  - 연결된 Tune 의 규칙이 0개면 규칙이 없다는 표시를 보인다.
  - 끈 상태: Tune 이 꺼졌다는 표시만 보인다.
  - 연결된 Tune 이 없으면 진입 시 표시하지 않는다.
  - 표시는 이전/다음 버튼 바를 가리지 않는다.

#### 셀렉터 소비 (GH-21)

- `FR#21` 색상은 `id` 필드로 셀렉터를 만들지 않고 저장된 `selector` 를 쓴다 (`spec_tune_edit.md` §6.7 M#6) [요구사항] GH-21
  - 근거: `#id` 셀렉터인 기존 저장분은 `selector` 가 이미 `#` + 같은 id 이고, 새 저장분은 안정 id 일 때만 이스케이프된 `#id` 로 시작한다 → `selector` 만 써도 결과가 같거나 더 정확하다.

  ```
  Given 색상 규칙의 id 가 div-gpt-ad-1712345678-0 이고 selector 가 구조 경로다
  When  페이지에 색을 적용한다
  Then  만들어진 CSS 규칙의 셀렉터는 구조 경로다
  ```

- `FR#22` 숨기기·클릭 연결·색상은 요소 정보를 `spec_tune_edit.md` FR#22 와 §6.7 공통 규칙으로 찾고 적용한다 [요구사항] GH-21

  ```
  Given selector 가 유효하지 않고, 저장된 속성이 {role: banner, aria-label: 광고} 인 div 숨기기 규칙이 있다
  When  페이지에 role="banner" 만 가진 다른 div 와 두 속성을 모두 가진 div 가 있다
  Then  두 속성을 모두 가진 div 만 숨겨진다
  ```

  ```
  Given 클릭 연결 규칙의 저장된 속성값에 작은따옴표가 있고 selector 가 유효하지 않다
  When  이전/다음 버튼을 누른다
  Then  스크립트 오류 없이 M#3 으로 찾은 첫 요소를 클릭하고, 없으면 아무것도 하지 않는다
  ```

## 4. 데이터 및 API 스펙

- `webpages` 행: `title`, `url`(마지막 위치로 갱신됨), `pluginId`(nullable, FK 없음) [as-built]
  - Tune 을 지워도 `pluginId` 는 남는다 → 조회 결과가 없으면 Tune 없음으로 다룬다 (FR#7).
- 규칙 형식·요소 정보 JSON 은 `spec_tune_edit.md` §4 를 따른다.
- 열람 → 편집 화면 진입 인자·결과와 테스트 주소 처리는 `spec_tune_edit.md` §4.4 한 곳에 둔다. 열람 화면은 현재 주소를 로드 주소로 넘기고, 결과로 FR#18 재적용·FR#19 연결을 판단한다 [요구사항] GH-22

- FR#19 의 연결은 편집 화면이 새 Tune 저장과 같은 트랜잭션에서 `webpages.pluginId` 를 바꿔 한다 (`spec_tune_edit.md` FR#21) → 저장과 연결 사이에 끊길 틈이 없다. 열람 화면은 연결을 쓰지 않는다.

## 5. 화면 및 UI/UX

### 5.1 흐름

- 메인(Web Pages 탭) → 항목 → 열람 화면 → 뒤로가기(FR#13) → 메인
- 열람 화면 → 핸들 → 빠른 메뉴 → Tune 편집 또는 이 페이지에 Tune 만들기 → 저장·취소 → 열람 화면 (FR#17~FR#19)

- 전체 WebView, 상단 진행 막대, 하단 이전·다음 버튼 바(FR#9) [as-built]
- 오른쪽 위 핸들, 상단 빠른 메뉴 툴바(FR#14, FR#15), Tune 상태 표시(FR#20) [요구사항] GH-22
- 빠른 메뉴와 이전·다음 버튼 바가 겹치지 않는다 [요구사항] GH-22

## 6. 동작 로직 및 정책

### 6.1 Tune 적용 시점 [FR#7] [FR#8]

- 규칙은 화면을 열 때 한 번 읽는다. 편집에서 저장하고 돌아올 때(FR#18, FR#19)만 다시 읽는다.
- 로드가 끝날 때마다 현재 주소·호스트와 상관없이 적용한다 [as-built]
  - 외부 호스트로 이동해도 같은 Tune 이 적용된다 → 범위 제한은 Out of Scope.
- 색은 `<style>` 태그 한 개에 규칙을 모아 넣는다 → 나중에 추가된 노드에도 CSS 로 적용되고 재적용 루프가 필요 없다.
  - 규칙은 `셀렉터, 셀렉터 * { 선언 !important; }` 형태 → 자식이 자기 색을 가진 경우까지 덮는다.
- 시작 위치는 목표 y 에 닿을 때까지 100ms 간격으로 최대 20회 시도하고, 사용자가 화면을 만지면 멈춘다 → 로드 직후에는 본문이 짧아 스크롤이 잘린다.
- Tune 을 끈 상태(FR#16)에서는 위 적용을 모두 건너뛰고 이전/다음 버튼 바와 두 번 탭을 끈다.

| 3 | 태그명 + 저장 속성 전부 일치 요소 전부 (M#3) [요구사항] GH-21 | 태그명 + 저장 속성 전부 일치 첫 요소 (M#3) [요구사항] GH-21 |

- 숨기기는 `body` 의 하위 노드 추가·삭제를 관찰해 다시 적용한다 → 무한 스크롤·지연 로드 광고까지 숨긴다 [as-built]

- 셀렉터 단계가 무효면 "찾지 못함" 으로 보고 다음 단계로 간다. 경로별 as-built 동작과 공통 규칙은 `spec_tune_edit.md` §6.7 한 곳에 둔다.

### 6.3 마지막 주소 기억 [FR#11]

- 원래 호스트는 화면을 열 때 저장 주소에서 구한다.
- Cloudflare 확인 페이지 주소를 저장하면 다음에 확인 페이지부터 열린다 → 해당 호스트는 저장하지 않는다.

### 6.4 뒤로가기 [FR#13]

- 시스템 뒤로가기는 가로채지 않고 플랫폼 기본 동작(화면 닫기)에 맡긴다 → 이전/다음 이동으로 쌓인 히스토리를 하나씩 되돌리지 않고 한 번에 목록으로 나간다.
- 이전 페이지 이동은 빠른 메뉴 '뒤로'가 WebView 히스토리로 직접 처리한다.
- 뒤로 간 페이지도 FR#11 에 따라 저장 주소가 된다 → "마지막으로 본 위치" 의미와 맞다.

### 6.5 편집 왕복 [FR#17] [FR#18]

- `testUrl` 은 Tune 의 대표 페이지다 → 열람 중 들어간 개별 글 주소로 덮어쓰지 않는다. 보장 방식은 `spec_tune_edit.md` §4.4.
- 저장 후 다시 로드하는 이유: 이미 적용된 숨기기는 인라인 스타일이라 규칙을 지운 경우 다시 로드해야 원래대로 보인다.
