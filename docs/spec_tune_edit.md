# page-tune — Tune 만들기·편집 (UC1)

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | spec_tune_edit |
| 작성자 | dohwan.ahn |
| 작성일 / 최종 수정일 | 2026-11-06 / 2026-11-07 |
| 버전 | 0.1 |
| 기준 커밋 ID | `7c25e2f` |

- **기능명:** Tune 만들기·편집 — 사이트에서 요소를 골라 숨기기·색상·클릭 연결·시작 위치를 Tune 으로 저장한다.
- **목적 (Why):**
  - Tune 이 없으면 앱이 일반 브라우저와 같다.
  - 요소 id 가 로드마다 바뀌는 사이트에서는 저장한 숨기기가 다음 방문에 적용되지 않는다 → 셀렉터가 `#그때의id` 로 저장되기 때문이다.
  - 편집 화면 하단 영역이 고정 높이라 요소를 고른 뒤 규칙 종류가 잘려 보이고, 저장하지 않은 변경이 취소·뒤로가기 한 번에 사라진다.

## 2. 목표 및 범위

### In Scope

- 현재 동작(as-built): Tune 목록·복제·삭제, 편집 화면, 요소 선택, 규칙 4종, 저장
- GH-18: 이 UC 화면의 문자열 리소스화와 한국어 (용어는 `specification.md` 공통 제약 "UI 문구")
- GH-19: 편집 화면 하단 영역 잘림, 저장하지 않은 변경 이탈 확인
- GH-20: Tunes 탭 빈 상태, 벡터 아이콘, 접근성 핵심
- GH-21: 셀렉터 안정화, 선택 시 매칭 수 표시, 기존 불안정 규칙 재선택 표시
- GH-22: 다른 화면이 로드 주소를 넘겨 편집 화면을 열고 저장 결과를 돌려받는 진입·결과 계약

### Out of Scope

- Tune 내보내기·가져오기
- 편집 흐름 단계화, 색상 선택 방식 변경, 클릭 트리거 입력 방식 변경
- Material 3 테마 전환, 라이트 테마, Compose
- 이미 저장된 불안정 셀렉터의 자동 복구 → 구조 정보가 저장돼 있지 않아 복구할 근거가 없다

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 사용자로서, 보기 싫은 요소를 화면에서 직접 골라 숨기고 싶다. 코드 없이 사이트별 보기를 만들기 위해서다 [as-built]
- `US#2` 사용자로서, 한 번 숨긴 요소가 다음 방문에도 숨겨져 있기를 원한다. 매번 다시 고르지 않기 위해서다 [요구사항] GH-21
- `US#3` 사용자로서, 편집 중 실수로 나가도 작업을 잃지 않기를 원한다 [요구사항] GH-19
- `US#4` 한국어 사용자로서, 개발자 용어 없이 한국어로 된 화면을 원한다 [요구사항] GH-18

### 3.2 기능 요구사항

#### Tune 목록 (Tunes 탭)

- `FR#1` Tune 목록은 최근 만든 순으로 이름을 보여주고, 항목이나 편집 아이콘을 누르면 편집 화면을 연다 [as-built]
- `FR#2` 복제는 규칙까지 포함한 새 Tune 을 만들고 이름 뒤에 복사본 표시를 붙인다. 원본은 바뀌지 않는다 [as-built]
- `FR#3` 삭제는 툴바 삭제 → 선택 모드(전체 선택 가능) → 확인 다이얼로그 순서로 하며, Tune 의 규칙도 함께 지워진다 [as-built]

  ```
  Given 선택 모드에서 아무것도 선택하지 않았다
  When  확인을 누른다
  Then  삭제하지 않고 선택 항목이 없다는 안내를 보인다
  ```

- `FR#4` Tune 이 하나도 없으면 목록 자리에 설명 한 줄과 "Tune 만들기" 행동 버튼을 보이고, 버튼은 새 Tune 편집 화면을 연다 [요구사항] GH-20

#### 편집 화면

- `FR#5` 주소를 입력해 불러오면 편집 WebView 에 연다. scheme 이 없으면 `https://` 를 붙이고, 현재 주소와 같으면 다시 로드한다 [as-built]
- `FR#6` 요소 선택 모드를 켜면 페이지를 눌러도 이동하지 않고 누른 요소가 강조·선택되며, 부모/자식으로 선택을 옮길 수 있다 [as-built]
  - 부모 이동은 `body` 직전에서 멈춘다.
  - 끄면 강조와 규칙 설정 영역이 사라진다.
  - 켠 채로 페이지가 다시 로드되면 선택 모드가 유지된다.
- `FR#7` 선택한 요소에 규칙 하나를 추가한다. 종류는 숨기기(기본)·클릭 연결·색상이다 [as-built]

  ```
  Given 클릭 연결의 트리거가 화면 두 번 탭(위/아래)이다
  When  영역 비율에 1~50 밖의 값이나 숫자가 아닌 값을 넣고 추가한다
  Then  규칙이 추가되지 않고 허용 범위 안내를 보인다 (빈칸이면 40 으로 추가한다)
  ```

  ```
  Given 색상에서 배경·글자색을 모두 고르지 않았다
  When  추가한다
  Then  규칙이 추가되지 않고 색을 하나 이상 고르라는 안내를 보인다
  ```

- `FR#8` 시작 위치 지정은 편집 WebView 의 현재 세로 스크롤(CSS px)을 Tune 의 시작 위치로 저장하며, Tune 당 하나만 남긴다 [as-built]
  - 값을 읽지 못하면 저장하지 않고 실패 안내를 보인다.
- `FR#9` 추가한 숨기기·색상은 즉시, 그리고 편집 WebView 의 페이지 로드마다 다시 적용된다 [as-built]
- `FR#10` 규칙 목록의 항목을 누르면 확인 없이 그 규칙을 지우고 페이지를 다시 로드한다 [as-built]
- `FR#11` 저장은 이름이 비어 있으면 거부하고 안내한다. 저장하면 이름·테스트 주소와 규칙 전체를 현재 편집 내용으로 바꾸고 화면을 닫는다 [as-built]
  - 저장되는 `testUrl` 은 항상 테스트 주소 칸의 값이다. 로드 주소 인자(§4.4)는 칸의 값을 바꾸지 않으므로 그것만으로 `testUrl` 이 바뀌지 않는다 [요구사항] GH-22
  - Tune 행 쓰기, 규칙 교체, 웹페이지 연결(FR#21)은 한 Room 트랜잭션으로 한다 → 중간에 프로세스가 끝나도 일부만 저장된 상태가 남지 않는다 [요구사항] GH-22 (현재는 Tune 행과 규칙을 따로 쓴다 [as-built])
  - 저장은 저장 계획 함수·저장 실행 함수·Room 어댑터 세 부분으로 나눈다 (§6.10) → 앞의 둘은 Android 의존 없이 단위 테스트한다 [요구사항] GH-25
- `FR#12` 하단 영역은 접힘/펼침 두 상태를 갖는 하단 시트이고, 펼친 상태에서 규칙 종류·종류별 옵션·추가 버튼이 잘리지 않고 보인다 [요구사항] GH-19
  - 요소를 선택하면 시트가 펼쳐진다.
  - 시트는 상단 핸들 영역을 끌 때만 움직인다 → 시트 안이나 WebView 의 스크롤·탭이 시트 드래그로 바뀌지 않는다.
  - 접힌 상태에서도 핸들, 요소 선택 토글, 취소·저장에 닿을 수 있다.

  ```
  Given 시트가 접혀 있고 요소 선택 모드가 켜져 있다
  When  페이지의 요소를 누른다
  Then  시트가 펼쳐지고 규칙 종류·옵션·추가 버튼이 스크롤 없이 보인다
  ```

- `FR#13` 저장하지 않은 변경이 있으면 취소 버튼과 시스템 뒤로가기에서 확인을 묻는다 [요구사항] GH-19

  ```
  Given 불러온 상태에서 이름·테스트 주소·규칙 목록 중 하나라도 바뀌었다
  When  취소 또는 뒤로가기를 누른다
  Then  "저장하지 않고 나가기 / 계속 편집" 확인을 보이고, 나가기를 고를 때만 화면을 닫는다
  ```

  ```
  Given 바뀐 것이 없다
  When  취소 또는 뒤로가기를 누른다
  Then  확인 없이 화면을 닫는다
  ```

#### 요소 셀렉터 (GH-21)

- `FR#14` 불안정 id(§6.2)는 셀렉터와 저장되는 `id` 에 쓰지 않는다 [요구사항] GH-21

  ```
  Given 선택한 요소의 id 가 로드마다 바뀌는 형태다 (e.g. div-gpt-ad-1712345678-0)
  When  요소를 선택한다
  Then  저장될 id 는 비어 있고, 셀렉터는 그 id 를 포함하지 않는 구조 경로다
  ```

- `FR#15` 셀렉터에 들어가는 id·class 는 CSS 이스케이프한다 → 숫자로 시작하거나 특수문자가 있는 이름도 유효한 셀렉터가 된다 [요구사항] GH-21
- `FR#16` 경로의 한 단계에서 class 가 모두 걸러지거나 없으면 `:nth-of-type(n)` 으로 위치를 고정한다 [요구사항] GH-21
- `FR#17` 경로는 안정 id 를 가진 가장 가까운 조상(`#id`)에서 시작하고, 없으면 문서 루트에서 시작한다 [요구사항] GH-21
- `FR#18` 요소를 선택하면 그 셀렉터가 현재 문서에서 매칭하는 요소 수를 함께 보인다 [요구사항] GH-21

  ```
  Given 셀렉터가 현재 문서에서 0개 또는 2개 이상을 매칭한다
  When  요소를 선택한다
  Then  매칭 수와 함께 경고를 보인다. 규칙 추가는 막지 않는다
  ```

  - 셀렉터가 유효하지 않으면 예외 없이 매칭 0 으로 보고 경고한다 (§6.7 M#1).

- `FR#19` 저장된 규칙 중 셀렉터가 불안정 id 에 기대는 것은 규칙 목록에 "다시 선택 필요" 로 표시한다 [요구사항] GH-21
  - 판정: 저장된 `id` 필드가 비어 있지 않고 불안정(§6.2)이다. `selector` 문자열은 보지 않는다.
  - 근거: 셀렉터가 `#id` 형태인 저장분은 요소에 id 가 있을 때만 생기고, 그때 `id` 필드에도 같은 원래 값이 저장된다 [as-built] → `id` 필드만으로 기존 저장분을 모두 가려낸다.
  - FR#14 를 따르는 저장분은 불안정 id 를 `id` 필드에도 셀렉터에도 넣지 않는다 (FR#14) → 표시되지 않는다. 셀렉터의 이스케이프된 `#id`(FR#15)를 해제해 판정할 필요가 없다.

- `FR#22` 요소 정보 JSON 을 읽는 모든 경로(숨기기·클릭 연결·색상·매칭 수, 편집 미리보기와 열람 모두)는 §6.7 공통 규칙을 따른다 → 한 규칙의 셀렉터·속성값·JSON 이 잘못돼도 예외 없이 다음 단계로 가고, 다른 규칙은 영향받지 않는다 [요구사항] GH-21

  ```
  Given 클릭 연결 규칙의 selector 가 유효하지 않은 CSS 이고, 저장된 속성값에 작은따옴표가 있다
  When  이전/다음 버튼을 누른다
  Then  스크립트 오류 없이 태그명·저장 속성이 모두 일치하는 첫 요소를 클릭하고, 없으면 아무것도 클릭하지 않는다
  ```

  ```
  Given 한 Tune 에 셀렉터가 유효하지 않은 색상 규칙과 정상 색상 규칙이 있다
  When  페이지에 색을 적용한다
  Then  정상 규칙은 적용되고, 잘못된 규칙은 태그명·저장 속성 전부 일치 요소에만 적용되며 저장 속성이 없으면 적용되지 않는다
  ```

#### 편집 화면 진입·결과 (GH-22)

- `FR#20` 편집 화면은 로드 주소 인자를 받으면 §4.4 의 진입 규칙대로 주소 칸과 편집 WebView 를 채운다 [요구사항] GH-22

  ```
  Given testUrl 이 A 인 기존 Tune 을 로드 주소 B 로 연다
  When  편집 화면이 열린다
  Then  주소 칸은 A, 편집 WebView 는 B 를 연다
  ```

- `FR#21` 편집 화면은 연결할 웹페이지 id 인자를 받으면, 새 Tune 을 저장할 때 같은 트랜잭션에서 그 웹페이지의 `pluginId` 를 새 Tune 으로 바꾼다 [요구사항] GH-22
  - 웹페이지 연결을 쓰는 곳은 이 저장 트랜잭션 한 곳뿐이다 (등록·편집 다이얼로그 제외) → 호출한 화면은 결과를 받은 뒤 DB 를 다시 읽기만 한다.
  - 그 웹페이지가 저장 시점에 없으면 연결 없이 Tune 만 저장한다.
  - 저장으로 닫히면 저장됨과 저장된 Tune id 를, 취소·뒤로가기로 닫히면 저장 안 됨을 호출한 화면에 돌려준다. 결과는 화면 갱신 신호일 뿐 연결의 근거가 아니다.

  ```
  Given 연결할 웹페이지 id 와 로드 주소로 새 Tune 편집 화면을 열었다
  When  규칙을 추가하고 저장한 직후 앱 프로세스가 종료된다
  Then  다시 실행하면 새 Tune 과 규칙이 있고 그 웹페이지에 연결돼 있다
  ```

  ```
  Given 연결할 웹페이지 id 로 새 Tune 편집 화면을 열었다
  When  취소한다
  Then  Tune 도 연결도 생기지 않고, 호출한 화면은 저장 안 됨을 받는다
  ```

- `NFR#4` 시스템 기본 아이콘(`@android:drawable/*`)을 앱 벡터 drawable 로 바꾼다 [요구사항] GH-20
  - 아이콘은 Material Symbols 의 벡터 XML 을 복사해 쓴다 (§6.6 D#6). 라이브러리 의존성이 아니다.
  - Apache 2.0 고지: 고지 원문을 `res/raw` 의 텍스트 파일 한 곳에 두고, 메인 화면 툴바 오버플로 메뉴의 "오픈소스 라이선스" 항목이 그 원문을 보여준다.
- `NFR#5` 불안정 id 판정 규칙은 Kotlin 상수 한 곳에 두고 JS 에 주입한다 → JVM 단위 테스트로 고정하고, 선택 스크립트와 저장 규칙 판정이 같은 규칙을 쓴다 [요구사항] GH-21
- `NFR#6` 런타임 의존성(APK 에 들어가는 것)을 추가하지 않는다. test 전용 의존성은 §6.8 의 JS 테스트 엔진(HtmlUnit)과 `org.json:json` 만 허용한다 → 추가 이유는 D#10 [요구사항]
- `NFR#7` 방문한 페이지가 정하는 문자열(요소 정보 JSON, 그 값으로 만든 CSS)은 Kotlin 의 JS 문자열 리터럴 함수 하나(§6.9)를 거쳐서만 스크립트에 들어가고, CSS 텍스트에는 §6.9 의 CSS 계약을 통과한 셀렉터와 이스케이프된 대체 셀렉터만 들어간다 → 페이지가 만든 값이 JS 코드나 별도 CSS 규칙으로 해석되지 않는다. 보안 경계이므로 조건마다 단위 TC 를 두고, 구현 PR 에서 조건을 하나씩 지워 해당 TC 가 실패하는지 확인해 결과를 PR 본문에 남긴다 [요구사항] GH-21 GH-25

## 6. 동작 로직 및 정책

### 6.1 셀렉터 생성 [FR#14] [FR#15] [FR#16] [FR#17]

| 단계 | as-built | GH-21 |
| --- | --- | --- |
| 선택 요소에 id | `#id` 로 즉시 반환 | 안정 id 면 `#` + 이스케이프 id, 불안정이면 구조 경로 |
| 경로 시작점 | 문서 루트(`html`) | 안정 id 를 가진 가장 가까운 조상, 없으면 루트 |
| 단계 표현 | class 속성이 있으면 숫자 없는 class 만 `.a.b`, class 속성이 없을 때만 `:nth-of-type` | 이스케이프한 class. 남는 class 가 없으면 `:nth-of-type` |
| 연결 | ` > ` | 같음 |

- 숫자가 들어간 class 를 거르는 현재 규칙은 유지한다 → 자동 생성 class 를 피하는 장치다.

### 6.2 불안정 id 판정 [FR#14] [FR#19] [NFR#5]

다음 중 하나면 불안정이다 (대소문자 무시).

| 규칙 | 예 | 근거 |
| --- | --- | --- |
| 숫자가 4개 이상 연속 | `x123456`, `post-20261106` | 타임스탬프·글 번호 → 페이지·로드마다 다르다 |
| 숫자를 하나 이상 포함한 16진 문자 8개 이상 연속 | `ad_8f3a9c2e1b` | 해시·UUID 조각 |
| 광고 슬롯 접두어 `google_ads_iframe_` `div-gpt-ad` `aswift_` | `google_ads_iframe_/123/x_0` | 광고 태그가 슬롯마다 붙이는 id |

- 안정 예: `header`, `nav-top`, `content1`, `deadbeef`(숫자 없음)
- 판정은 이스케이프하기 전의 원래 id 값에 한다.
- 오판정 비용이 비대칭이다 → 안정 id 를 불안정으로 보면 셀렉터가 길어질 뿐이지만, 반대면 숨기기가 다음 방문에 실패한다. 그래서 넓게 잡는다.

### 6.3 매칭 수 [FR#18]

- 선택 직후 `document.querySelectorAll(selector).length` 를 선택 정보와 함께 보낸다.
- 0 → 다시 로드했을 때 찾지 못할 가능성 경고. 2 이상 → 의도보다 많이 숨길 가능성 경고.
- 같은 광고 틀이 여러 개인 경우 2 이상이 의도일 수 있다 → 경고만 하고 막지 않는다.

### 6.4 저장하지 않은 변경 판정 [FR#13]

- 화면을 연 시점(새 Tune 은 빈 값)의 이름·테스트 주소·규칙 목록과 현재 값을 비교한다.
- 규칙 비교는 id 를 뺀 내용(`actionType` `targetSelector` `triggerType` `gestureAreaPercent` `styleCss`)과 순서로 한다 → 새로 추가한 규칙은 id 가 0 이라 id 로는 비교할 수 없다.
- "화면을 연 시점의 값"은 §4.4 의 진입 규칙을 적용한 직후 값이다 → 로드 주소 인자로 열고 아무것도 바꾸지 않으면 변경 없음이다.
- 편집 WebView 가 연 주소는 비교 대상이 아니다 → 저장되지 않는 값이다.
- 판정은 Android 의존 없는 함수로 둔다 → 단위 테스트 대상.

### 6.5 뒤로가기

- 편집 화면의 뒤로가기는 화면 나가기(FR#13)다. 편집 WebView 의 페이지 히스토리로 가지 않는다 → 테스트 주소를 다시 불러오는 경로(FR#5)가 이미 있다.
- `OnBackPressedCallback` 으로 처리한다 → targetSdk 36 에서는 `onBackPressed()` 가 호출되지 않는다 ([Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16)).

| `D#10` JS 테스트 엔진 [NFR#5] [NFR#6] [NFR#7] | HtmlUnit 과 `org.json:json` 을 `testImplementation` 으로만 추가 (APK 미포함) | 수동 확인만 유지, JS 엔진 + jsoup shim, 계측 테스트 | 셀렉터·매칭 규칙은 GH-21 의 핵심이고 경로마다 같은 규칙을 지켜야 한다(D#8) → 사람 손 확인으로는 회귀를 막지 못한다. 기술 스택 목록 밖 의존성이므로 이유를 여기 둔다. 비교와 미검증 항목은 §6.8. `org.json:json` 은 JVM 단위 테스트의 `android.jar` `org.json` 이 스텁이라 `JSONObject` 를 쓰는 함수(e.g. `getColorScriptFor`)를 실행하려면 실제 구현이 필요해서 넣는다. 한계: JSON.org 구현이라 Android 런타임의 `org.json` 과 세부 동작(이스케이프·숫자 표기 등)이 다를 수 있다 |

### 6.7 요소 정보 소비 경로와 공통 규칙 [FR#18] [FR#22]

요소 정보 JSON(§4.3)을 읽는 경로를 전부 센 결과다. "무효"는 셀렉터가 CSS 로 파싱되지 않는 경우, "특수 속성"은 속성값에 따옴표·역슬래시가 있거나 속성 이름이 CSS 식별자가 아닌 경우(e.g. `@click`)다.

| 경로 | 호출 지점 | 셀렉터 무효 [as-built] | 특수 속성 [as-built] | JSON 파싱 실패 [as-built] | 공통 규칙 적용 후 |
| --- | --- | --- | --- | --- | --- |
| 숨기기 | 열람 페이지 로드 완료, 편집 미리보기(FR#9) | 2단계 예외 → 규칙별 `try` 에 잡혀 그 규칙만 실패, 3단계에 가지 않음 | 3단계가 `[k='v']` 문자열을 조립 → 예외 → 그 규칙만 실패 | `JSON.parse` 예외 → 그 규칙만 건너뜀 | 2단계 "찾지 못함" → 3단계 (M#2, M#3) |
| 클릭 연결 | 열람 이전/다음 버튼, 위/아래 두 번 탭 | 4단계 `querySelector` 가 `try` 밖 → 스크립트 전체 예외, 클릭 없음 | 3단계 `querySelector` 가 `try` 밖 → 예외, 4단계에 가지 않음 | 요소 정보를 JS 코드에 그대로 삽입 → 문법 오류면 스크립트 전체 실패 | 단계별 예외 없음, 3단계 M#3, 요소 정보는 M#5 |
| 색상 | 열람 페이지 로드 완료, 편집 미리보기(FR#9) | CSS 파서가 그 규칙 하나만 버림 → 예외 없음, 다른 규칙 영향 없음. 단 `}` 등이 든 셀렉터는 규칙을 벗어나 뒤 텍스트가 별도 규칙이 된다 | 속성을 쓰지 않음 | Kotlin 에서 그 규칙만 제외 | 저장 `selector` 사용(M#6), §6.9 CSS 계약 통과 여부에 따라 M#4 |
| 매칭 수 (FR#18) | 편집 화면 요소 선택 | — (신규) | — | — | 무효면 매칭 0 + 경고 (M#1) |
| 규칙 목록 표시 | 편집 화면 규칙 목록 | 문자열로 표시만 함 | 해당 없음 | "찾을 수 없는 요소" 류 표시 | 변경 없음 → CSS·DOM 을 실행하지 않는다 |
| 선택 결과 표시 | 편집 화면 요소 선택 직후 | 문자열로 표시만 함 | 해당 없음 | 오류 표시 | 변경 없음 |
| 재선택 판정 (FR#19) | 편집 화면 규칙 목록 | 해당 없음 (`id` 필드만 읽음) | 해당 없음 | 판정하지 않고 위 표시를 따른다 | 변경 없음 |
| 복제 (FR#2) | Tunes 탭 | 해석하지 않고 문자열을 복사 | 해당 없음 | 해당 없음 | 변경 없음 |

공통 규칙

- `M#1` 한 규칙의 요소 정보가 잘못돼도 예외를 스크립트 밖으로 내지 않는다 → 그 규칙만 영향받고 나머지 규칙 처리는 계속된다.
- `M#2` 셀렉터를 쓰는 단계에서 셀렉터가 무효면 그 단계를 "찾지 못함" 으로 보고 다음 단계로 간다.
- `M#3` 속성 단계는 태그명이 같고 저장된 속성이 모두 일치하는 요소만 찾는다.
  - 속성값은 셀렉터 문자열을 조립하지 않고 값끼리 비교한다 → 특수 속성에서도 예외가 없다.
  - 저장된 속성이 없으면 찾지 못함이다 → 태그명만으로는 찾지 않는다.
  - 근거: 속성 하나만 일치해도 찾는 방식은 `role` 같은 흔한 속성으로 무관한 요소를 숨기거나 클릭한다.
- `M#4` CSS 로 적용하는 경로는 M#3 과 같은 조건을 속성 셀렉터 `태그[이름="값"]…` 로 표현한 대체 셀렉터를 쓴다. 태그·이름은 CSS 식별자로, 값은 CSS 문자열로 이스케이프한다. 원래 셀렉터가 §6.9 CSS 계약을 통과하면 원래 셀렉터 규칙 + 그 셀렉터가 무효일 때만 동작하는 대체 규칙을, 통과하지 못하면 대체 규칙만 쓴다.
  - 한계: 셀렉터가 유효하지만 0개를 찾는 경우 색상은 대체 셀렉터를 쓰지 않는다 → 같은 요소 정보라도 숨기기·클릭은 3단계로 찾고 색상은 적용되지 않는다 (D#8).
- `M#5` 요소 정보는 JS 코드로 삽입하지 않고 §6.9 의 리터럴 함수로 만든 문자열 리터럴로 넘겨 스크립트 안에서 `JSON.parse` 한다 → 파싱 실패는 M#1 로 처리된다 [NFR#7].
- `M#6` `id` 필드로 셀렉터를 다시 만들지 않는다 → 셀렉터 안 id 의 이스케이프는 선택 스크립트(FR#15) 한 곳에서만 한다. `getElementById` 단계는 셀렉터가 아니므로 그대로 쓴다.

### 6.8 JS 테스트 수단 [NFR#5] [NFR#6]

- 대상: 셀렉터 생성, 불안정 id 판정의 JS 측 적용, 요소 찾기(M#1~M#3, M#5), 매칭 수.
- 이 스크립트들은 `document.querySelectorAll`·`getElementById`·`CSS.escape`·`MutationObserver`·클릭 이벤트를 쓴다 → JS 엔진만으로는 부족하고 DOM 구현이 함께 있어야 한다.

| 후보 | DOM API 제공 방식 | 판단 |
| --- | --- | --- |
| HtmlUnit (`org.htmlunit:htmlunit`) | 브라우저를 흉내 내는 헤드리스 구현이 DOM·CSS 셀렉터 엔진·이벤트를 직접 제공하고, 내장 JS 엔진(Rhino 기반)에서 스크립트를 실행한다 | 권장. 스크립트 문자열을 수정 없이 실행해 DOM 결과를 단언할 수 있다. 셀렉터 해석은 브라우저 동작을 목표로 한 자체 구현이다 → Chromium 과 다를 수 있어 실제 WebView 확인을 남긴다 |
| Rhino 또는 GraalJS + jsoup | jsoup 은 Java 용 HTML 파서다. JS 에서 쓸 `document`·`Element` 객체를 직접 연결하는 shim 을 만들어야 한다 | 기각. shim 이 테스트 대상보다 커진다. jsoup 셀렉터 문법은 CSS 와 다른 자체 문법이라 이스케이프·무효 셀렉터 판정 결과가 브라우저와 다를 수 있다 → 검증하려는 바로 그 부분을 믿을 수 없다 |
| GraalJS 단독 / Rhino 단독 | DOM 없음 | 기각. 순수 함수만 테스트할 수 있는데, 대상 로직 대부분이 DOM 질의다 |
| 계측 테스트 (에뮬레이터 WebView) | 실제 Chromium | 기각. 검증 명령(`testDebugUnitTest`)에 들어가지 않아 CI 에서 돌지 않는다. 실제 WebView 확인은 수동 TC 로 남긴다 |

- 테스트 방법: 픽스처 HTML 을 엔진에 올리고 → Kotlin 이 만든 스크립트 문자열을 그대로 실행 → DOM 상태(숨김 스타일, 클릭 핸들러 호출 기록, 브리지로 받은 요소 정보)를 단언한다.
  - 선택 스크립트가 부르는 `AndroidBridge` 는 테스트에서 JS 객체로 대신해 넘어온 요소 정보를 기록한다.
- 미검증 항목 → GH-21 구현 PR 에서 Red 테스트를 만들 때 실제로 돌려 확인한다. 이번에는 문서 조사만 했다.
  - HtmlUnit 이 `CSS.escape` 를 제공하는지 → 없으면 CSSOM 사양 알고리즘의 테스트 전용 대체 구현을 픽스처에 넣는다. 이때는 대체 구현을 검증하는 셈이므로 이스케이프의 WebView 동작은 TC#17 수동 재확인이 필요하다.
  - `MutationObserver` 콜백이 DOM 변경 후 실행되는지 → 안 되면 최초 적용만 단위로 보고, 재적용은 수동으로 남긴다.
  - Android 단위 테스트 클래스패스(`android.jar` 스텁)에서 HtmlUnit 과 그 전이 의존성이 충돌 없이 로드되는지.
  - 버전: 5.x 는 Java 17 이상을 요구한다 ([HtmlUnit 5.0.0 공지](https://htmlunit.github.io/htmlunit-blog/2026/05/24/release-5-0-0.html)). 이 저장소의 테스트 바이트코드 대상은 17 이다 → 5.x 를 우선 시도하고 정확한 버전은 구현 PR 에서 고정한다.
  - 위 셋 중 하나라도 해결되지 않으면 그 PR 에서 소유자에게 알리고, 해당 TC 를 수동으로 되돌린다.

### 6.9 코드 삽입 경계 [NFR#7]

- Kotlin 이 만든 스크립트 문자열은 `evaluateJavascript` 로 방문 중인 페이지 컨텍스트에서 실행된다. 페이지가 정한 문자열이 리터럴 밖으로 새면 그 페이지가 앱의 주입 스크립트 자리에서 코드를 실행한다.

| 삽입 지점 | 들어가는 값 | 값의 출처 | as-built | 요구 |
| --- | --- | --- | --- | --- |
| 숨기기 스크립트 | 요소 정보 JSON 목록 | 페이지 | `JSONArray` 문자열을 JS 코드로 삽입 → JSON 문법을 JS 가 해석 | 규칙마다 리터럴 함수 → 스크립트 안에서 `JSON.parse` |
| 클릭 스크립트 | 요소 정보 JSON | 페이지 | 저장 문자열을 그대로 코드로 삽입 | 같음 |
| 색상 스크립트 | CSS 텍스트 (셀렉터, 대체 셀렉터의 속성값) | 페이지 + 사용자가 고른 색 | `\` `'` 개행만 직접 치환 | 리터럴 함수 |
| 시작 위치 스크립트 | 정수 y | 편집 WebView | `Int` 보간 | 변경 없음 → 정수라 코드가 될 수 없다 |
| 선택 스크립트의 불안정 id 규칙 (NFR#5) | Kotlin 상수 | 개발자 | — (신규) | 경계 밖이지만 같은 리터럴 함수로 넣는다 |
| 편집 화면의 고정 스크립트 | 상수 | 개발자 | 그대로 | 변경 없음 |

리터럴 함수 계약

- 입력 문자열을 작은따옴표로 감싼 JS 문자열 리터럴로 바꾼다. 결과를 JS 에서 평가하면 입력과 같은 문자열이 된다.
- 치환 표 → 조건마다 TC#30 사례가 있고 mutation 의 단위다.

| 조건 | 입력 | 출력 | 근거 |
| --- | --- | --- | --- |
| E1 | `\` | `\\` | 뒤 문자의 이스케이프를 막는다 |
| E2 | `'` | `\'` | 리터럴 종료를 막는다 |
| E3 | `"` | `\"` | 호출부가 큰따옴표 리터럴로 바뀌어도 안전하다 |
| E4 | LF, CR | `\n`, `\r` | 리터럴 안 줄바꿈은 문법 오류다 |
| E5 | U+2028, U+2029 | `\u2028`, `\u2029` | ES2019 이전 엔진에서는 줄 종결자다 |
| E6 | `<` | `\u003C` | 스크립트가 HTML 에 들어가는 경우의 `</script>` 종료를 막는다 |
| E7 | 그 밖의 U+0000~U+001F | `\uXXXX` | 제어 문자가 리터럴을 깨거나 숨지 않게 한다 |

- `org.json` 의 따옴표 처리에 기대지 않고 순수 Kotlin 함수로 둔다 → 테스트의 `org.json` 은 JSON.org 구현이고 런타임은 Android 구현이라(D#10), 그것에 기대면 테스트가 통과해도 실제 경계 동작을 보장하지 못한다.
- 기존 색상 스크립트 테스트(`spec_page_view.md` TC#9)의 기대값(`\'`, 날 개행 없음)은 이 계약과 같다 → 그 테스트는 바꾸지 않는다.

CSS 계약 [GH-25]

- JS 리터럴 함수는 CSS 텍스트가 JS 코드가 되는 것만 막는다. CSS 텍스트 안에서 저장된 셀렉터가 규칙을 벗어나는 것은 별도로 막아야 한다.
  - as-built: `buildColorCss` 가 저장 `selector` 를 그대로 `셀렉터, 셀렉터 * { … }` 에 넣는다 → 셀렉터에 `}` 가 있으면 규칙이 일찍 닫히고 뒤 텍스트가 별도 CSS 규칙으로 해석된다.
  - `@supports not selector(원래 셀렉터)` 도 같은 문자열을 넣는다 → `)` 로 조건이 일찍 닫힌다.
  - 영향은 CSS 주입에 한정된다 → 페이지는 원래 자기 CSS 를 통제하므로 권한 상승은 아니지만, NFR#7 이 경계로 선언했으므로 같은 기준으로 막는다.
- 원래 셀렉터는 아래 조건을 모두 통과할 때만 CSS 텍스트에 넣는다 (CSS 안전 판정 함수, 순수 Kotlin). 하나라도 걸리면 그 규칙은 원래 셀렉터 규칙과 `@supports` 블록 없이 대체 규칙만 쓴다.

| 조건 | 거부하는 입력 | 근거 |
| --- | --- | --- |
| C1 | `{` `}` | 블록 경계 → 규칙을 닫거나 새로 연다 |
| C2 | `;` `@` | 선언·at-rule 경계 |
| C3 | `"` `'` | 문자열을 열어 뒤 텍스트를 삼킨다 |
| C4 | `/*` `*/` | 주석으로 뒤 텍스트를 숨기거나 드러낸다 |
| C5 | `(` `)` 중 `:nth-of-type(숫자)` 의 괄호가 아닌 것 | `selector(…)` 조건을 일찍 닫는다. 선택 스크립트가 만드는 괄호는 이것뿐이다 |
| C6 | `[` `]` | 선택 스크립트의 `selector` 에는 속성 셀렉터가 없다 → 있으면 선택 스크립트 산출물이 아니다 |
| C7 | 문자열 끝의 `\` | 뒤에 붙는 구분 문자를 이스케이프해 규칙 구조를 바꾼다. 중간의 `\` 는 FR#15 의 정상 이스케이프라 허용한다 |
| C8 | `<`, 개행·제어 문자 | 선택 스크립트 산출물에 없는 문자 → 거부해도 정상 규칙을 잃지 않는다 |

- 대체 셀렉터는 태그·속성 이름을 CSS 식별자로, 값을 CSS 문자열로 이스케이프해 만든다 → 위 조건 없이도 규칙을 벗어나지 않는다 (TC#29).
- 판정은 허용 목록이 아니라 규칙 경계 문자의 거부 목록이다 → 선택 스크립트가 FR#15 로 이스케이프한 셀렉터(`#\31 abc`, `.a\:b`)를 그대로 통과시키기 위해서다.

### 6.10 저장 트랜잭션 구조 [FR#11] [FR#21]

| 부분 | 하는 일 | Android 의존 | 검증 |
| --- | --- | --- | --- |
| 저장 계획 함수 | 편집 상태(이름, 주소 칸, 규칙 목록, `plugin_id` 유무, 연결할 웹페이지 id)로 "무엇을 쓸지" 를 만든다: Tune 행 값, 교체할 규칙 목록, 연결 대상 또는 없음. 이름이 비면 계획 없음 | 없음 | 단위 TC#32 |
| 저장 실행 함수 | 계획을 받아 저장소 인터페이스의 트랜잭션 블록 한 번 안에서 Tune 쓰기 → 규칙 교체 → 연결을 차례로 호출한다 | 없음 (저장소는 인터페이스) | 단위 TC#33, fake 저장소 |
| Room 어댑터 | 저장소 인터페이스 구현. 트랜잭션 블록 = Room 트랜잭션 한 번, 각 연산 = DAO 호출 하나 | Room | 수동 TC#27 |

- fake 저장소는 트랜잭션 블록 안의 쓰기를 임시로 모았다가 블록이 정상 종료될 때만 반영하고, 블록 밖 쓰기를 기록한다 → "블록 밖 쓰기 없음" 과 "중간 예외 시 반영 없음" 을 단언할 수 있다.
- 연결 대상 규칙: 새 Tune 이고 연결할 웹페이지 id 가 있을 때만 연결한다. 기존 Tune 이면 인자가 있어도 연결하지 않는다 (§4.4).
- 자동화하지 않는 범위: Room 어댑터가 실제로 원자적인지.
  - Room 트랜잭션을 실행하려면 SQLite 가 필요하다 → JVM 단위 테스트에서는 Robolectric, 아니면 기기 계측 테스트가 있어야 한다.
  - Robolectric 은 새 test 의존성이고(NFR#6 허용 목록 밖), 계측 테스트는 검증 명령(`testDebugUnitTest`)에 들어가지 않는다 → 둘 다 채택하지 않는다.
  - 남는 위험은 어댑터가 트랜잭션 블록을 Room 트랜잭션으로 연결하지 않는 실수 하나다 → 어댑터는 그 연결과 DAO 위임만 두어 분기가 없게 하고, 정상 경로는 TC#27 로 본다.
