# page-tune — 웹페이지 등록·Tune 적용 열람 (UC2)

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | spec_page_view |
| 작성자 | dohwan.ahn |
| 작성일 / 최종 수정일 | 2026-11-06 / 2026-11-06 |
| 버전 | 0.1 |
| 기준 커밋 ID | `7c25e2f` |

- **기능명:** 웹페이지 등록·Tune 적용 열람 — 웹페이지를 Tune 과 묶어 등록하고, 열 때마다 Tune 을 적용해 본다.
- **목적 (Why):**
  - UC1 에서 만든 Tune 을 실제로 쓰는 경로다.
  - 열람 화면에 조작 UI 가 없다 → 뒤로가기를 누르면 이전 페이지가 아니라 화면이 닫히고, 새로고침·주소 공유·Tune 확인 수단이 없다.
  - Tune 을 고치려면 목록 → Tune 탭 → 편집 → 주소 재입력 → 저장 → 다시 열기를 거쳐야 한다.

## 2. 목표 및 범위

### In Scope

- 현재 동작(as-built): 웹페이지 목록·등록·편집·삭제, 열람 화면, Tune 적용(숨기기·색·시작 위치·이전/다음·두 번 탭), 마지막 주소 기억
- GH-18: 이 UC 화면의 문자열 리소스화와 한국어
- GH-19: 웹페이지 다이얼로그 제목 표시, 열람 화면 뒤로가기
- GH-20: 웹페이지 탭 빈 상태, 벡터 아이콘, 접근성 핵심
- GH-21: 색 적용의 불안정 id 처리, 숨기기의 유효하지 않은 셀렉터 처리
- GH-22: 열람 화면 빠른 메뉴, Tune 상태 표시, 열람 중 Tune 편집 후 즉시 반영

### Out of Scope

- Tune 적용 범위를 URL·호스트로 제한하는 기능 → 현재처럼 이동한 모든 페이지에 적용된다 (§6.1)
- 다른 앱의 링크를 받아 여는 기능, 주소창 입력, 탭·히스토리
- 오류 화면, `intent://`·다운로드 등 외부 링크 처리
- 삭제 되돌리기, 목록 카드 개편, 온보딩

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 사용자로서, 자주 보는 페이지를 Tune 과 함께 등록해 한 번에 다듬어진 화면으로 열고 싶다 [as-built]
- `US#2` 사용자로서, 글을 넘겨 보다가 뒤로가기로 이전 글로 돌아가고 싶다 [요구사항] GH-19
- `US#3` 사용자로서, 보고 있는 페이지에서 바로 Tune 을 고치고 결과를 바로 보고 싶다 [요구사항] GH-22
- `US#4` 사용자로서, 지금 Tune 이 적용됐는지 알고 필요하면 잠깐 끄고 원래 페이지를 보고 싶다 [요구사항] GH-22

### 3.2 기능 요구사항

#### 웹페이지 목록 (Web Pages 탭)

- `FR#1` 목록은 최근 등록 순으로 제목·주소·연결된 Tune 이름(없으면 없음 표시)을 보여주고, 항목을 누르면 열람 화면을, 편집 아이콘을 누르면 편집 다이얼로그를 연다 [as-built]
- `FR#2` 등록·편집 다이얼로그는 제목·주소·Tune(없음 포함)을 받는다 [as-built]

  ```
  Given 제목이나 주소가 비어 있다
  When  저장한다
  Then  저장하지 않고 모두 입력하라는 안내를 보인다
  ```

  - 주소에 scheme 이 없으면 `https://` 를 붙여 저장한다.
- `FR#3` 삭제는 툴바 삭제 → 선택 모드(전체 선택 가능) → 확인 다이얼로그 순서다. 선택 없이 확인하면 안내만 한다 [as-built]
- `FR#4` 다이얼로그 제목("웹페이지 추가" / "웹페이지 편집")이 배경과 구분돼 읽힌다 [요구사항] GH-19
- `FR#5` 웹페이지가 하나도 없으면 목록 자리에 설명 한 줄과 "웹페이지 추가" 행동 버튼을 보이고, 버튼은 등록 다이얼로그를 연다 [요구사항] GH-20

#### 열람 화면

- `FR#6` 열람 화면은 상태바를 숨기고 노치까지 쓰는 전체화면이며, 내비게이션 바만 피한다. 로딩 중에는 상단 진행 막대를 보인다 [as-built]
- `FR#7` 화면을 열 때 웹페이지와 연결된 Tune 의 액션을 한 번 읽고, 저장된 주소를 연다 [as-built]

  ```
  Given 웹페이지 id 가 없거나 DB 에 없다
  When  열람 화면을 연다
  Then  오류 안내 후 화면을 닫는다
  ```

  ```
  Given 연결된 Tune 이 없거나 삭제됐다
  When  열람 화면을 연다
  Then  Tune 없이 페이지를 연다
  ```

- `FR#8` 페이지 로드가 끝날 때마다 색 → 숨기기 → 시작 위치 순으로 적용한다 (§6.1) [as-built]
- `FR#9` 이전/다음 클릭 연결이 있으면 하단에 이전·다음 버튼 바를 보이고, 누르면 연결된 요소를 클릭한다 [as-built]
- `FR#10` 위/아래 두 번 탭 클릭 연결이 있으면, 화면 위쪽 N% 또는 아래쪽 N% 에서 두 번 탭할 때 연결된 요소를 클릭한다 [as-built]
  - N 은 위쪽 액션의 값을 우선하고, 없으면 아래쪽 액션의 값이다.
- `FR#11` 같은 호스트 안에서 이동하면 웹페이지의 저장 주소를 이동한 주소로 바꾼다 → 다음에 열면 마지막 위치에서 시작한다 [as-built]
  - 다른 호스트, 호스트명에 `cloudflare` 또는 `challenges` 가 들어간 주소, 파싱할 수 없는 주소로 이동하면 바꾸지 않는다.
- `FR#12` 페이지 로드가 끝날 때마다 쿠키를 디스크에 내린다 → 앱이 종료돼도 사이트 통과 쿠키가 남는다 [as-built]
- `FR#13` 시스템 뒤로가기는 WebView 에 이전 페이지가 있으면 그 페이지로, 없으면 열람 화면을 닫는다 [요구사항] GH-19

  ```
  Given 열람 화면에서 링크로 두 번 이동했다
  When  뒤로가기를 세 번 누른다
  Then  두 번은 이전 페이지로 돌아가고, 세 번째에 목록으로 돌아간다
  ```

#### 빠른 메뉴·Tune 상태 (GH-22)

- `FR#14` 열람 중 한 번의 동작으로 빠른 메뉴를 열고 닫을 수 있다. 평소에는 화면을 가리지 않는다 [요구사항] GH-22
  - 여는 방법과 자동 숨김 `[확인필요]` §6.6 D#3
- `FR#15` 빠른 메뉴 항목은 뒤로, 새로고침, 주소 공유, Tune 켜기/끄기, 이 페이지에서 Tune 편집이다 [요구사항] GH-22
  - 뒤로는 FR#13 과 같다.
  - 주소 공유는 현재 주소를 시스템 공유 시트로 보낸다.
  - 연결된 Tune 이 없으면 Tune 켜기/끄기는 비활성이다.
- `FR#16` Tune 을 끄면 페이지를 다시 로드하고 Tune 을 적용하지 않는다. 켜면 다시 로드하고 적용한다 [요구사항] GH-22
  - 끈 상태의 유지 범위 `[확인필요]` §6.6 D#4

  ```
  Given Tune 이 적용된 페이지를 보고 있다
  When  빠른 메뉴에서 Tune 을 끈다
  Then  숨겨졌던 요소와 원래 색이 보이고, 이전/다음 버튼과 두 번 탭 동작이 멈춘다
  ```

- `FR#17` 이 페이지에서 Tune 편집을 고르면 연결된 Tune 의 편집 화면을 현재 주소로 연다 [요구사항] GH-22
  - 편집 화면의 테스트 주소 칸과 편집 WebView 는 현재 주소를 쓰고, 저장해도 Tune 의 `testUrl` 은 바뀌지 않는다.
- `FR#18` 편집 화면에서 저장하고 돌아오면 열람 화면이 액션을 다시 읽고 Tune 을 켠 상태로 페이지를 다시 로드한다. 취소하고 돌아오면 아무것도 바꾸지 않는다 [요구사항] GH-22

  ```
  Given 열람 중 Tune 편집으로 숨기기를 하나 추가했다
  When  저장하고 돌아온다
  Then  열람 화면에서 그 요소가 숨겨져 있다
  ```

- `FR#19` 연결된 Tune 이 없는 웹페이지에서 Tune 편집 항목의 동작 `[확인필요]` §6.6 D#5 [요구사항] GH-22
- `FR#20` 열람 화면에 들어오거나 Tune 을 켜고 끌 때 Tune 상태를 잠깐 보인다 [요구사항] GH-22
  - 보이는 내용 `[확인필요]` §6.6 D#6

#### 셀렉터 소비 (GH-21)

- `FR#21` 색상은 저장된 `id` 가 안정 id 일 때만 `#id` 를 쓰고, 아니면 `selector` 를 쓴다 (판정은 `spec_tune_edit.md` §6.2) [요구사항] GH-21

  ```
  Given 색상 액션의 id 가 div-gpt-ad-1712345678-0 이고 selector 가 구조 경로다
  When  페이지에 색을 적용한다
  Then  만들어진 CSS 규칙의 셀렉터는 구조 경로다
  ```

- `FR#22` 숨기기에서 `selector` 가 유효하지 않은 CSS 라도 그 액션을 포기하지 않고 속성 매칭(§6.2 3단계)으로 넘어간다 [요구사항] GH-21

## 6. 동작 로직 및 정책

### 6.1 Tune 적용 시점 [FR#7] [FR#8]

- 액션은 화면을 열 때 한 번 읽는다. 편집에서 돌아올 때(FR#18)만 다시 읽는다.
- 로드가 끝날 때마다 현재 주소·호스트와 상관없이 적용한다 [as-built]
  - 외부 호스트로 이동해도 같은 Tune 이 적용된다 → 범위 제한은 Out of Scope.
- 색은 `<style>` 태그 한 개에 규칙을 모아 넣는다 → 나중에 추가된 노드에도 CSS 로 적용되고 재적용 루프가 필요 없다.
  - 규칙은 `셀렉터, 셀렉터 * { 선언 !important; }` 형태 → 자식이 자기 색을 가진 경우까지 덮는다.
- 시작 위치는 목표 y 에 닿을 때까지 100ms 간격으로 최대 20회 시도하고, 사용자가 화면을 만지면 멈춘다 → 로드 직후에는 본문이 짧아 스크롤이 잘린다.
- Tune 을 끈 상태(FR#16)에서는 위 적용을 모두 건너뛰고 이전/다음 버튼 바와 두 번 탭을 끈다.

### 6.2 요소 찾기 [FR#8] [FR#9] [FR#10] [FR#22]

| 순서 | 숨기기 (모두 숨김, DOM 변경마다 재적용) | 클릭 연결 (첫 요소 하나 클릭) |
| --- | --- | --- |
| 1 | `getElementById(id)` | `getElementById(id)` |
| 2 | `querySelectorAll(selector)` | 같은 태그 중 정규화한 텍스트가 서로 포함 관계인 첫 요소 |
| 3 | 각 속성 `[k='v']` 매칭의 합집합 | 각 속성 `[k='v']` 첫 매칭 |
| 4 | — | `querySelector(selector)` |

- 숨기기는 `body` 의 하위 노드 추가·삭제를 관찰해 다시 적용한다 → 무한 스크롤·지연 로드 광고까지 숨긴다 [as-built]
- 숨긴 뒤 보이는 자식이 없는 부모는 `body` 직전까지 함께 접는다 → 빈 틀이 남지 않는다 [as-built]
- 2단계에서 셀렉터 오류가 나면 3단계로 넘어간다 [요구사항] GH-21 (현재는 그 액션 전체가 실패한다 [as-built])

### 6.3 마지막 주소 기억 [FR#11]

- 원래 호스트는 화면을 열 때 저장 주소에서 구한다.
- Cloudflare 확인 페이지 주소를 저장하면 다음에 확인 페이지부터 열린다 → 해당 호스트는 저장하지 않는다.

### 6.4 뒤로가기 [FR#13]

- `OnBackPressedCallback` 으로 처리한다 → targetSdk 36 에서는 `onBackPressed()` 가 호출되지 않는다 ([Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16)).
- 뒤로 간 페이지도 FR#11 에 따라 저장 주소가 된다 → "마지막으로 본 위치" 의미와 맞다.

### 6.5 편집 왕복 [FR#17] [FR#18]

- `testUrl` 은 Tune 을 처음 만들 때 고른 대표 페이지다 → 열람 중 들어간 개별 글 주소로 덮어쓰지 않는다.
- 저장 후 다시 로드하는 이유: 이미 적용된 숨기기는 인라인 스타일이라 액션을 지운 경우 다시 로드해야 원래대로 보인다.
